# AGENTS.md

Ikki ERP — Bun monorepo. Apps: `apps/server` (Elysia + Drizzle API), `apps/web` (React 19 + Vite + TanStack), `apps/e2e` (Playwright). (`apps/web-archive` is a retired frontend — ignore it.) No `packages/*` exist yet despite the workspace glob.

This file is the single source of truth for conventions and commands. `CLAUDE.md` only routes here. Read the **Server architecture** section below before building server features. Note: several commands (`bun run verify`, `bun run build`, `db:*`) do NOT exist at the repo root — they are per-app.

## Toolchain quirks

- Linter is **oxlint**, formatter is **oxfmt** — NOT eslint/prettier. Config: `.oxlintrc.json`, `.oxfmtrc.json`.
- Server lint is type-aware (`oxlint --type-aware`); web/root is not.
- TypeScript uses `allowImportingTsExtensions` + `verbatimModuleSyntax`. Use `import type` for type-only imports.
- Server path aliases (see `apps/server/tsconfig.json`): `@/*` → `apps/server/src/*`, plus `@/db`, `@/infra/*`, `@/shared/*`, `@/modules/*`.

## Commands

Run per-app commands with `bun --filter @ikki/server <script>` or from the app dir.

Root:

- `bun run dev:server` / `bun run dev:web`
- `bun run lint` / `bun run format` / `bun run check` (lint + format:check + knip)
- `bun run test:e2e` (Playwright, needs server + web running)

Server (`apps/server`):

- `bun run verify` — lint + typecheck + knip + check-deps (the real gate; run before finishing server work)
- `bun run typecheck` (`tsc --noEmit`)
- `bun run test` — `NODE_ENV=test bun test --bail --timeout 30000`. Tests live in `src/tests/`. Integration tests need a migrated + seeded DB (`bun run test:db:reset`) and run concurrently (`bunfig.toml`): build fixtures with unique codes (`src/tests/helpers/fixtures.ts`, `uniqueSuffix()`), never assert global counts.
- `bun test src/tests/integration/location.test.ts` — run a single file
- `bun run build` — compiles `dist/server` + `dist/migrate` (+ `dist/migrations`); `bun run start` runs the binary
- `bun run check-deps` — circular dependency check via dpdm

Web (`apps/web`):

- `bun run verify` — lint + typecheck + vitest (the gate; run before finishing web work)
- `bun run test` — vitest
- `bun run typecheck`

## Database (from `apps/server`)

- `bun run db:generate --name <descriptive_name>` (from schema changes) → `bun run db:migrate`
- Production migrations run via the compiled `scripts/migrate.ts` (`/app/migrate`, Fly `release_command`) before new machines start.
- DB driver is `pg` (node-postgres pool, `DB_POOL_MAX`). On Neon use the pooled (`-pooler`) endpoint.
- `bun run db:studio`, `bun run db:seed`
- **Destructive scripts are guarded**: reset/seed only run if `NODE_ENV=test` + `DATABASE_URL` contains `test-user`, OR `NODE_ENV=development` + URL contains `dev-user` (`scripts/db-scripts-helper.ts`). Point env at the right DB or they silently no-op.
- **Pre-release: no backward compatibility.** The app is still in research/development; there is no production data to preserve. Breaking API/schema changes are fine. If existing data conflicts with a migration (or migration history diverges), reset the database (`NODE_ENV=development DATABASE_URL=… bun run scripts/db-scripts-helper.ts all` = drop + migrate + seed) instead of writing data-preserving migrations.

## Agent config (omp)

- `.omp/config.yml` — team-wide omp settings (skill filtering, LSP diagnostics on edit). Model roles stay per-user in `~/.omp/agent/config.yml`.
- `.omp/lsp.json` — language servers: `tsgo` (TypeScript 7 `tsc --lsp` from `apps/web`; the root `typescript` is 6.x, which has no `--lsp`), `oxlint --lsp`, `oxfmt --lsp` (format on write). omp only auto-detects servers from cwd, so start omp at the repo root.
- `.agents/rules/*.md` — stream rules that fire only when an edit/command matches (repo `null` returns, npm/eslint). Test with `omp ttsr test --rule <file> ...`. Add a rule for a repeated agent mistake instead of growing this file. Generated files (`routeTree.gen.ts`) are already blocked by omp's built-in `edit.blockAutoGenerated`.

## Secrets (age-encrypted)

Env files and sensitive configs are stored in the repo **encrypted** with [age](https://github.com/FiloSottile/age) — ciphertext (`*.age`) committed, plaintext gitignored. Managed via `scripts/secrets.sh {encrypt|decrypt|status}`. See `secrets/README.md` for setup and workflow. Machine-local scratch (incl. the private key `.local/age.key`) lives in `.local/`, which is fully gitignored — see `.local/README.md`.

## Generated files

- `apps/web/src/routeTree.gen.ts` is TanStack Router generated — never edit by hand.

There is currently **no server→web contract codegen**. `apps/web/src/config/endpoint.ts` is hand-written. DTOs are defined per-slice in the web app.

## Server architecture

Vertical slices under `apps/server/src/modules/<module>/`. A module groups related slices, each slice is a folder of layered files:

- `*.contract.ts` — Zod DTOs (request/response). Compose with spread-shape: `...UserMutationDto.shape`, `...zc.AuditBasic.shape`. Shared primitives come from `@/shared/schema` (`zp`, `zq`, `zc`).
- `*.repo.ts` — Drizzle data access behind an `IXxxRepo` interface. Finders return the DTO or `undefined` (never `null`); `insert`/`update` return an `EntityRef` (`{ id }`) or `undefined`. Every method takes an optional `db?: DbContext` for transactions.
- `*.service.ts` — business logic. Public entry points are `handle*` methods. They check conflicts (`checkConflict`), stamp audit fields (`stampCreate`/`stampUpdate` from `@/shared/audit`), and write through `mutate()` (`@/shared/service/mutate.ts`): it runs the work + audit record in one UoW transaction, then **invalidates cache** after commit. UoW retries on deadlock/serialization failure, so transaction callbacks MUST be re-runnable — no cache/network side effects inside them.
- Simple CRUD slices compose `createCrudRepo` (`@/infra/database/crud.repo.ts`, + `paginate()`), `crudRoutes` (`@/server/crud-route.ts`, standard `/list` `/detail` `/create` `/update` `/remove`) and `defineEntityErrors` (`@/shared/errors/entity-errors.ts`). Complex domains (pos order, inventory, production) stay hand-written. Large append-only lists also expose keyset `/…/cursor` endpoints (`@/infra/database/keyset.ts`).
- Stock: multi-line movements lock balances in `(locationId, materialId)` order (`lockBalances`) to avoid deadlocks. POS order create is idempotent on `externalRef`.
- Authorization is per location (`@/server/plugins/rbac.plugin.ts`). `permission: 'x.y'` requires the permission at the `locationId` named in the query and/or body (else at the `x-location-id` header; no header = global grants only) and resolves an `actor` bound to that permission into the handler. Services MUST call `actor.assertCan(record.locationId)` on records loaded by id, and lists with an optional location filter MUST filter by `inScope(actor.allowedLocations(), table.locationId)` (`@/infra/database`). Multi-location operations assert the acting side in the service (transfers: create/ship at the source, receive at the destination, read from either end). Company-wide writes (roles, users, global assignments) call `actor.assertCan(null)`. Covered by `src/tests/integration/location-access.test.ts`.
- API docs: Scalar at `/openapi` (spec `/openapi/json`, off in production), configured in `@/server/openapi.ts`. **Authorize** logs in through `POST /auth/token` (OAuth2 password grant) and keeps the token; `X-Location-ID` is a security scheme. Every route MUST have `detail.summary` and exactly one tag from `TAG_GROUPS` (instance `tags`, or per-route `detail.tags` when an instance mixes resources); `crudRoutes` takes `tag` + `entity` and writes its own summaries. Add `description` only for non-obvious behaviour; never restate the permission (the RBAC macro appends it). Requests render in Zod input mode, `zRes` envelopes in output mode. Enforced by `src/tests/integration/openapi.test.ts`.
- `*.internal.ts` — module-private helpers, error factories, unique-field lists.
- Module wiring: `*.module.ts`, `*.route.ts` (Elysia), `index.ts` (barrel exporting a `ModuleDescriptor`, registered in `src/app.ts`; `dependsOn` is validated eagerly and layers may only depend downward).

Shared building blocks live in `apps/server/src/shared/` (`auth`, `cache`, `errors`, `http`, `schema`, `uow`, `audit`, ...) and infrastructure in `apps/server/src/infra/` (`database`, `cache`, `redis`, `session`, `audit`). One BentoCache instance (`@/infra/cache`): L1 memory, plus Redis L2 + bus when `REDIS_URL` is set so invalidations reach every machine; use BentoCache tags for grouped invalidation, never in-process key tracking. Postgres errors are mapped centrally (`@/infra/database/pg-errors.ts`: 23505/23503 → 409, 23514 → 422). Audit stamps (`createdBy`/`updatedBy`/`createdAt`/`updatedAt`) are applied through the stamp helpers, not by hand.

## Deploy / CI

- CI (`.github/workflows/ci.yml`) runs server format check, `verify`, migrate+seed, tests and build on PRs and pushes to `dev`/`main`. Server deploys to Fly.io only after CI succeeds on `main` (`deploy-server.yml`, `workflow_run`). Build context is repo root (allowlist `.dockerignore`); Dockerfile/config at `apps/server`. Probes: `/health` (liveness), `/ready` (DB).
- Active dev branch is `dev`; `main` triggers deploys.
- Commit style: conventional prefixes, frequently with emoji (e.g. `✨ feat:`, `🔧 fix:`, `♻️ refactor:`).
