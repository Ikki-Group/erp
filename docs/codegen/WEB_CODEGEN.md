# Web Codegen (contract-driven)

The web API layer is **generated from server contracts** — a single typed source
of truth. No regex parsing, no hand-duplicated method/DTO declarations.

## How it works

1. Each server module declares its HTTP surface once via `defineContract(...)`
   in its `*.contract.ts`, referencing the real Zod DTOs:

   ```ts
   // apps/server/src/modules/location/location.contract.ts
   import { defineContract } from '@/shared/contract/define-contract'

   export const locationContract = defineContract({
     feature: 'location', // web feature folder + endpoint namespace
     entity: 'location', // file basename + query-key resource
     prefix: '/location', // Elysia route prefix
     dtoSource: 'location/location.contract.ts',
     dtos: { LocationDto, LocationFilterDto, LocationCreateDto, LocationUpdateDto },
     endpoints: {
       list: { get: '/list', query: LocationFilterDto, ok: [LocationDto] }, // [X] = paginated
       detail: { get: '/detail', query: zc.RecordId, ok: LocationDto },
       create: { post: '/create', body: LocationCreateDto, ok: zc.RecordId },
       update: { put: '/update', body: LocationUpdateDto, ok: zc.RecordId },
       remove: { delete: '/remove', body: zc.RecordId, ok: zc.RecordId },
     },
   })
   ```

   - `feature` — the `features/<feature>` folder and endpoint namespace.
   - `entity` — the entity within the feature. For a single-entity feature it
     equals `feature` (e.g. `location`). For a multi-entity feature it is the
     sub-entity (e.g. feature `iam`, entities `user` / `role` / `assignment`).
   - `dtos` — registry of `Name → schema` for every DTO the codegen must emit.
     The generator recovers each emitted **identifier by object identity**, so
     you never write the name twice. Schemas NOT in `dtos` (e.g. `zc.RecordId`)
     are treated as shared validation primitives (imported from `@/lib/validation`).
   - **Endpoint shape:** the HTTP **method is the key** (`get`/`post`/…), its
     value is the path. `query`/`body` = input (kind inferred). `ok` = success
     output; wrap in `[ ]` for a **paginated** list. `auth?` defaults to true.

2. Register the contract in `apps/server/scripts/generate-web.ts`
   (`CONTRACT_PATHS`).

3. Run the generator (from the repo root, or from `apps/server`):

   ```sh
   bun run generate:web            # all registered contracts
   bun run generate:web location   # one feature
   bun run generate:web:preview    # dry-run, prints target paths
   ```

   The generator lives in `apps/server/scripts/` so it is covered by the server
   `tsconfig` (`scripts/**`) — full type-aware lint + `@/` alias resolution.
   The root `generate:web` scripts delegate via `bun --filter @ikki/server`.

## Generated output

```
apps/web/src/features/<feature>/<feature>.dto.ts  # merged DTOs (all entities), import → @/lib/validation
apps/web/src/features/<feature>/<entity>.api.ts   # typed apiFactory calls (one per entity)
apps/web/src/features/<feature>/index.ts          # barrel (generated + manual block)
apps/web/src/config/endpoint.gen.ts               # URL map for all features
```

- **DTOs are merged into one `<feature>.dto.ts`** per feature (all entities'
  contract sources concatenated). Duplicate exported names across the merged
  sources emit a `⚠️` warning at generation time.
- **API stays one file per entity** (`<entity>.api.ts`) so multi-entity features
  keep `userApi` / `roleApi` separate.
- **Single-entity** feature (e.g. `location`): `location.dto.ts`, `location.api.ts`.
- **Multi-entity** feature (e.g. `iam`): one `iam.dto.ts` + `user.api.ts`,
  `role.api.ts`, ... at the `iam/` root.

Endpoint config nests only for multi-entity features:
`endpoint.location.list` (single) vs `endpoint.iam.user.list` (multi).

The feature `index.ts` barrel is generated (dto + api exports per entity) with a
`/* --- manual exports (preserved) --- */` marker; hand-written exports
(`./components`, `./pages`, `./utils`) go **below** the marker and are preserved
across regeneration.

All generated files start with `// AUTO-GENERATED by scripts/generate-web.ts — DO NOT EDIT.`

## Rules

- **Never hand-edit generated files** (dto, api, endpoint.gen, or the block
  above the barrel marker). Change the server contract and re-run.
- Import DTOs/APIs from the feature **barrel** (`@/features/location`), never a
  deep path — flat file layout means deep paths break on regeneration.
- The DTO copy is verbatim except: it strips the `defineContract` import + the
  `export const …Contract` block, rewrites `@/shared/schema` → `@/lib/validation`,
  and rewrites `@/modules/<x>` → `@/features/<x>` (cross-feature DTO imports are
  additionally **re-exported** so the merged dto is the single import surface).
- Validation helpers on web live in `@/lib/validation`. All web features import
  from there (the old `@ikki/api-contract` alias has been removed).
- Web keeps `ky` + `apiFactory` + TanStack Query. `.query(params)` →
  `queryOptions`; `.mutationFn` → `useMutation`.

## Validation parity (server ↔ web)

The DTO copy works **verbatim** because `@/lib/validation` (web) mirrors the
**inferred output types** of `@/shared/schema` (server), symbol-for-symbol
(`zp`, `zc`, `zq`, `z`, response helpers). Only the runtime weight differs — web
is deliberately lighter (type-first, minimal transforms).

| Primitive        | Server (`@/shared/schema`)                          | Web (`@/lib/validation`)          | Inferred type |
| ---------------- | --------------------------------------------------- | --------------------------------- | ------------- |
| `zp.decimal`     | `union([string,number]).transform(String)`          | `z.string()` (lightweight)        | **`string`**  |
| `zp.uuid`        | `z.uuid()`                                           | `z.uuid()`                        | `string`      |
| `zp.dateNullable`| `date.nullable()`                                    | `date.nullable()`                 | `Date \| null`|
| `zc.email`       | `z.email().max(255).toLowerCase()`                   | same                              | `string`      |
| `zq.boolean`     | `string.optional().transform(v => v==='true'\|\|v==='1')` | same                         | `boolean`     |
| `zq.withPagination` | helper present                                    | helper present                    | —             |

**Key rule — decimals are strings.** Money/quantity columns are Postgres
`numeric` → serialized as **strings** over JSON. Both sides infer `string`, so:

- Contracts may write `zp.decimal.default('0')` and copy as-is (no rewrite).
- **Forms** hold numbers for UX; convert `number → String(x)` when building a
  mutation body (at the submit boundary). Convert `Number(x)` on the read side
  only where numeric math/formatting is needed.

When adding/altering a primitive on either side, keep the **inferred output
type** identical across both files, or the copied DTOs will drift. Web may use a
lighter runtime (e.g. `z.string()` vs a transform) as long as the type matches.
